# 视觉与交互 QA 报告

日期：2026-09-02

## 方法与边界

- 以 `docs/design/home-approved.png`、`docs/design/result-approved.png` 为基准。
- 用与小程序 WXML/WXSS 同变量和结构的本地浏览器验收页，在 432×911（设计稿 864×1821 的逻辑尺寸）检查并截图。
- 另检查 360×800 与 430×932：页面横向溢出均为 0，窄屏粘贴按钮缩到 96px。
- 2026-09-02 已在微信开发者工具 Stable 2.02.2608060、基础库 3.17.2、362×783 模拟器中自动验证首页到保存成功的 Mock 主流程。
- 新增画质选择后，官方 CLI `open` 与 `auto` 再次通过项目载入和编译。Windows 界面捕获可唯一识别开发者工具窗口，但连续两次返回 `SetIsBorderRequired 0x80004002`，因此没有对三段式画质控件伪造截图结论；该控件的真机/模拟器视觉仍需人工确认。
- Gate A 仍为 `PARTIAL`：五页面、字体放大及 360–430px 多机型人工检查尚未全部完成；Gate B、D 仍为 `NOT VERIFIED`。

## 对照结果

1. 信息层级一致：系统导航、状态提示、权益提示、主输入、双按钮、法律说明、工具入口。
2. 色彩一致：主色 `#07C160`，背景 `#F7F8FA`，白色表面和轻边框。
3. 形态一致：输入区、提示卡、媒体预览和按钮采用 8–12px 圆角；间距保持紧凑。
4. 首页操作比例一致：主按钮占剩余宽度，粘贴按钮固定宽度；360px 下保持可点击尺寸。
5. 结果页结构一致：完成状态、16:9 预览、平台/标题/媒体信息、版权提示、进度、主次按钮。
6. 核心交互通过：粘贴 → 提取结果 → 点击保存 → 24 小时广告弹窗 → 完整观看 → 自动进度 → 保存成功。
7. 控制台无 error/warn；本地唯一 404 为无业务影响的 `favicon.ico`。

## 有意偏差

- 根据用户提供的变现参考录屏，在首页和结果页增加 Banner 广告区；无真实广告单元时生产环境不渲染。
- 用户最新要求覆盖原 V1 单画质假设：首页新增原视频、720P、540P 三段式选择；结果页显示实际分辨率和编码，不照搬参考录屏的“源 1/源 2”命名。
- 结果页使用新生成的无文字山景 Mock 封面，不复制设计稿中的具体图片。
- 开发模式明确显示 Mock 提示，避免把模拟观看/保存误写成真实收益或相册写入。
