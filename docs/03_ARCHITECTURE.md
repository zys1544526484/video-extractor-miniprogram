# 架构

微信小程序 → HTTPS FastAPI → Auth / Persistent Parse Queue / Parser Registry / Persistent Media Session → 公开媒体源。

前端不解析平台页面。后端统一提取 URL、识别平台、选择 Parser，并通过短期 media token 提供预览和下载。用户输入永远不能直接成为代理目标。

解析采用 SQLite 持久任务和单节点单并发 worker。小程序创建任务后每 1.5 秒查询进度，并把 `job_id` 写入本地存储；页面重开可继续查询。服务重启时，未过期的排队中/处理中任务重新排队。

已通过 SSRF、MIME 和大小元数据校验的 HTTPS MP4 可以使用按需代理快路径；用户预览或保存时才传输正文。需要 DASH 合并、重封装、格式兼容或降档的媒体才先写入 `TEMP_DIR`。数据库中的媒体访问 token 只保存 SHA-256 摘要，本地媒体路径只保存受控相对路径。

任务和媒体记录默认保留 24 小时，媒体访问 token 默认只有效 900 秒并可在记录有效期内重新签发。异常或过期临时文件由独立 `TEMP_FILE_TTL_SECONDS` 清理，当前默认 90000 秒，用于覆盖 24 小时媒体记录；三种期限不得混写。

媒体管道把源文件上限与微信成品上限分离：公开源文件默认最多暂存 2GiB，并以分块流式写入和 Range 续传降低网络中断影响；最终用 FFprobe 校验。超过 180MiB、容器/编码不兼容或高于所选画质时，FFmpeg 自动降档并编码为 H.264 + AAC，最终只生成一个 MP4。服务器剩余磁盘低于 10GiB 时拒绝新任务。
